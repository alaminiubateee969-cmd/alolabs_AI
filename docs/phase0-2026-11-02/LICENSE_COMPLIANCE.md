# Phase 0 — licence and dependency compatibility

No dependency has been approved for new integration. The accompanying matrix records GitHub's detected SPDX label, not licence verification or legal advice. `NOASSERTION`, missing labels, custom, mixed or per-directory licences require review of the actual files and distribution terms. GitHub's project-level licence never clears transitive dependencies, models, datasets, fonts, content, trademarks or services.

Before any integration, identify exact commit and distribution path, read all applicable licence/NOTICE files, trace transitive components and model weights, check commercial use and copyleft/network/distribution obligations, preserve notices and modifications where required, and obtain owner/legal review. AGPL/GPL and custom terms deserve particular scrutiny; no incompatibility is presumed solely from the label. Cursor has per-plugin licence files; Dify, Rescript and Billion Context metadata reports `NOASSERTION`. Existing instruction-only copies and their notices require a separate per-file verification; their presence is not blanket approval of whole projects.

Compatibility findings: `package.json` lists both npm and Bun lockfiles, Next/React/Prisma and diverse SDKs; language/API coexistence does not demonstrate compatible dependencies. Native desktop/Android tools cannot be imported directly into a Next.js server and must be independent, isolated worker services where appropriate. Python/Go/Java/media stacks add operational overhead. Model toolcalls, API versions, authentication and database drivers require contract tests. No lockfile regeneration, vulnerability scan, package installation or license scanner ran during Phase 0. Earlier dependency findings in `ALO_LABS_DEPENDENCY_SECURITY.md` are historical, not current scan results.
